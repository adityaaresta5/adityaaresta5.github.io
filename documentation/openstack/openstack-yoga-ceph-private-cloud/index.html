Kunci versi dan bentuk topologi sebelum menyentuh server

Dokumen menetapkan Ubuntu 22.04 LTS, OpenStack Yoga, dan Ceph Quincy. Desainnya: tiga controller HA, compute KVM, SDN OVN, dan Cinder yang memakai Ceph sebagai backend. Semua langkah berikutnya bergantung pada keputusan ini.

Apa yang kamu lakukan

  1. Catat versi yang diwajibkan: Ubuntu 22.04 LTS, OpenStack Yoga, Ceph Quincy.
  2. Tetapkan peran host: controller01–03 untuk control, network, monitoring, dan storage; hyperconverged01 untuk compute dan storage.
  3. Pastikan platform virtualisasi memakai KVM, SDN memakai OVN, dan Cinder memakai Ceph.
  4. Simpan tabel versi dan peta host di satu tempat sebelum instalasi dimulai.
Hasil yang diharapkan: satu tabel versi, peran host, dan jaringan yang disepakati—tanpa angka yang masih diperdebatkan.

Kenapa ini penting

Kolla-Ansible mengikat container ke rilis OpenStack. Ceph menyimpan data dengan format dan keyring yang harus cocok dengan rilisnya. Mencampur rilis di tengah jalan membuat deploy gagal atau, lebih buruk, berhasil tetapi tidak kompatibel.

Analogi praktis

Ini seperti menuang pondasi sebelum memasang pipa. Betonnya bisa saja cepat kering, tetapi letak pipa yang salah tidak bisa diperbaiki dengan mengecat ulang.

Jebakan umum

Menganggap semua host sama. Di dokumen, controller juga menjalankan peran network, monitoring, dan storage—bukan hanya control plane.

Memakai rilis “terbaru”. Yoga dan Quincy adalah pasangan yang ditetapkan; jangan menggantinya karena tersedia versi lain.

Pro-tip

Buat satu halaman “source of truth” berisi versi, hostname, IP lima jaringan, dan VIP. Semua perintah di langkah 2–9 akan merujuk ke halaman itu, bukan ke ingatan.

Susun lima jaringan 190–194, lalu terapkan Netplan

Desain fisik memakai dua spine dan dua leaf; host memakai dua bond. API di VLAN 190, public endpoint 191, tunnel 192, storage 193, dan Ceph public 194. VIP internal 192.168.190.10, VIP eksternal 192.168.191.10.

Apa yang kamu lakukan

  1. Backup Netplan: cd /etc/netplan, lalu cp 00-installer-config.yaml 00-installer-config.yaml.bak.
  2. Buat bond0 dari enp129s0f0 + enp194s0f0 dengan mode 802.3ad, MTU 9000, dan hash layer3+4.
  3. Buat bond1 dari enp194s0f1 + enp129s0f1 dengan parameter yang sama.
  4. Tambahkan VLAN 190, 191, 192 di bond0; VLAN 193, 194 di bond1.
  5. Isi alamat per host sesuai tabel DNS hal. 60–61, lalu jalankan netplan apply.
Hasil yang diharapkan: lima VLAN aktif, host dapat saling ping di 190–194, dan rute default lewat 192.168.190.1.

Kenapa ini penting

Kolla-Ansible memetakan peran layanan ke nama interface, bukan ke VLAN. Kalau api_interface, tunnel_interface, dan neutron_external_interface salah, container tetap hidup tetapi layanan tidak bisa saling bicara.

Analogi praktis

Lima VLAN seperti lima jalur khusus di jalan tol. Semua mobil bisa lewat, tetapi kalau ambulans diarahkan ke jalur kargo, kemacetan bukan salah mobilnya.

Jebakan umum

Menerapkan Netplan lewat SSH tanpa konsol cadangan. Salah nama interface membuat koneksi putus dan host tidak bisa dijangkau.

MTU tidak konsisten. Bond dan tunnel memakai 9000, sedangkan VLAN 190/191 di dokumen memakai 1500. Jangan menyamakan semuanya tanpa alasan.

Pro-tip

Tulis nama interface dan VLAN di samping console sebelum mengedit. Dokumen memakai nama enp129s0f0, enp194s0f0, dan seterusnya—nama ini bisa berbeda di hardware lain.

Rapikan host: tuned, ulimit, waktu, SSH, dan hostname

Sebelum OpenStack dipasang, setiap host harus punya profil jaringan yang tepat, batas file descriptor yang cukup, waktu yang seragam, dan nama yang bisa diselesaikan host lain. Semua langkah di sini dijalankan di semua host OpenStack, kecuali distribusi SSH key.

Persiapan host · hal. 64–68 (kapitalisasi perintah dinormalkan)
# 1. Profil jaringan
apt install tuned
tuned-adm profile network-throughput

# 2. Batas resource — /etc/security/limits.conf
* soft memlock unlimited
* hard memlock unlimited
* soft nofile 1024000
* hard nofile 1024000
* hard core 0

# 3. Waktu dan paket dasar
timedatectl set-timezone Asia/Jakarta
timedatectl
apt update -y
apt upgrade -y
apt install net-tools tree -y

# 4. SSH key (dijalankan di controller01)
ssh-keygen -t rsa
cat ~/.ssh/id_rsa.pub

# 5. Hostname — satu nilai per host, jangan dijalankan berurutan di host yang sama
hostnamectl set-hostname controller01
hostnamectl set-hostname controller02
hostnamectl set-hostname controller03
hostnamectl set-hostname hyperconverged01

Apa yang kamu lakukan

  1. Pasang tuned, lalu aktifkan profil network-throughput.
  2. Tambahkan batas memlock unlimited dan nofile 1024000 di /etc/security/limits.conf.
  3. Set zona waktu Asia/Jakarta, lalu update dan upgrade paket.
  4. Buat SSH key, distribusikan public key ke ~/.ssh/authorized_keys semua host.
  5. Set hostname yang unik, lalu isi /etc/hosts dengan seluruh nama dan IP internal/public/tunnel/storage/Ceph public.
Hasil yang diharapkan: setiap host dapat me-resolve nama host lain, login SSH tanpa password, dan melaporkan zona waktu WIB.

Kenapa ini penting

Ansible menghubungi host berdasarkan nama di inventory. Jika hostname, /etc/hosts, dan DNS tidak sepakat, ansible -i multinode all -m ping gagal sebelum deploy dimulai.

Analogi praktis

Hostname itu nomor rumah, /etc/hosts itu buku alamat lingkungan. Kalau buku alamat menulis nomor lama, kurir akan mengetuk rumah yang salah.

Jebakan umum

Menjalankan empat hostnamectl di satu host. Setiap host hanya memakai satu nama; daftar di atas adalah peta, bukan urutan.

Lupa menyalin key ke semua host. Bootstrap Kolla berjalan dari controller01 ke seluruh host; satu host tanpa key akan menghentikan play.

Pro-tip

Dokumen menulis .SSH dan SSH-keygen. Di Linux, direktori dan perintah bersifat case-sensitive: gunakan ~/.ssh dan ssh-keygen.

Bootstrap Kolla-Ansible dari satu host

Semua perintah orkestrasi dijalankan dari controller01. Di sinilah venv Python, Kolla-Ansible, inventory multinode, globals.yml, password, sertifikat, dan bootstrap server disiapkan.

controller01 · bootstrap Kolla-Ansible · hal. 73–79
# 1. Dependensi dan virtual environment
apt update -y
apt-get install -y python3-dev libffi-dev gcc libssl-dev python3-selinux \
  python3-setuptools python3-venv python3-pip
mkdir ~/openstack && cd ~/openstack
python3 -m venv os-venv
source os-venv/bin/activate

# 2. Ansible dan Kolla-Ansible untuk Yoga
pip install -U pip
pip install 'ansible>=4,<6'
pip install git+https://opendev.org/openstack/kolla-ansible@unmaintained/yoga

# 3. Direktori config dan contoh berkas
mkdir -p /etc/kolla
chown $USER:$USER /etc/kolla
cp -r ~/openstack/share/kolla-ansible/etc_examples/kolla/* /etc/kolla
cp ~/openstack/share/kolla-ansible/ansible/inventory/multinode .
kolla-ansible install-deps

# 4. ansible.cfg
sudo mkdir -p /etc/ansible
cat<<EOF | sudo tee /etc/ansible/ansible.cfg
[defaults]
host_key_checking=False
pipelining=True
forks=100
EOF

# 5. Password, sertifikat, bootstrap
ansible -i multinode all -m ping
kolla-genpwd
kolla-ansible -v -i multinode certificates
cat /etc/kolla/certificates/ca/root.crt >> /etc/ssl/certs/ca-certificates.crt
kolla-ansible -v -i multinode bootstrap-servers

Apa yang kamu lakukan

  1. Pasang dependensi Python, buat venv os-venv, lalu aktifkan.
  2. Pasang Ansible versi >=4,<6 dan Kolla-Ansible dari branch unmaintained/yoga.
  3. Salin globals.yml, passwords.yml, dan inventory multinode ke lokasi yang ditentukan.
  4. Isi inventory: control/network/compute/monitoring/storage, lalu [deployment] localhost.
  5. Isi globals.yml untuk VIP, interface, OVN, Ceph, dan TLS; jalankan kolla-genpwd.
  6. Generate certificate, tambahkan root CA ke trust store, lalu bootstrap server.
Hasil yang diharapkan: ansible all -m ping sukses di semua host, passwords.yml terisi, dan bootstrap-servers selesai tanpa failed.

Kenapa ini penting

Kolla-Ansible adalah satu-satunya jalur deploy OpenStack di dokumen. Semua container, sertifikat, dan konfigurasi HA diturunkan dari inventory dan globals.yml. Kesalahan di sini akan muncul jauh kemudian sebagai layanan yang tidak saling terhubung.

Analogi praktis

Inventory itu daftar tamu, globals.yml itu denah meja. Kalau daftar tamu dan denah tidak sinkron, katering datang ke ruangan yang salah.

Jebakan umum

Menjalankan deploy dari beberapa host. Pilih controller01 dan konsisten di seluruh langkah.

Lupa menambahkan root CA ke trust store. TLS internal/external diaktifkan di globals.yml; tanpa CA, verifikasi layanan bisa gagal.

Pro-tip

Sebelum deploy, jalankan kolla-ansible -i multinode prechecks. Dokumen memakainya di fase scale-out hal. 91; kebiasaan yang sama berguna di deploy pertama.

Bootstrap Ceph: satu MON pertama, lalu sebarkan kunci

Sebelum Ceph bisa di-bootstrap, paket cephadm dan repo Quincy harus tersedia di controller01, dan delapan NVMe data di setiap host harus dibersihkan. Setelah itu MON pertama dijalankan di jaringan public 194, cluster network memakai 193, lalu public key Ceph disebarkan ke tiga host lain.

Prasyarat + bootstrap Ceph · hal. 68, 79–80 · password dashboard diganti placeholder
# Prasyarat — controller01 (hal. 68)
apt install cephadm ceph-common -y
cephadm add-repo --release quincy
rm /etc/apt/sources.list.d/ceph.list
apt update

# Bersihkan 8 NVMe data — semua node. Ini menghapus signature disk!
sgdisk -Z /dev/nvme0n1
sgdisk -Z /dev/nvme1n1
sgdisk -Z /dev/nvme2n1
sgdisk -Z /dev/nvme3n1
sgdisk -Z /dev/nvme4n1
sgdisk -Z /dev/nvme5n1
sgdisk -Z /dev/nvme6n1
sgdisk -Z /dev/nvme7n1

# Semua node
mkdir -p /etc/ceph

# controller01 — ceph.conf
cat<<EOF > ceph.conf
[global]
public network = 192.168.194.0/24
cluster network = 192.168.193.0/24
EOF

# controller01 — bootstrap MON pertama
cephadm bootstrap \
  --config ceph.conf \
  --mon-ip 192.168.194.11 \
  --cluster-network 192.168.193.0/24 \
  --initial-dashboard-user admin \
  --initial-dashboard-password '<password-dashboard-anda>' \
  --allow-fqdn-hostname \
  --skip-monitoring-stack

# controller01 — sebarkan public key ke host lain
ssh-copy-id -f -i /etc/ceph/ceph.pub controller02
ssh-copy-id -f -i /etc/ceph/ceph.pub controller03
ssh-copy-id -f -i /etc/ceph/ceph.pub hyperconverged01

Apa yang kamu lakukan

  1. Di controller01, pasang cephadm dan ceph-common, tambahkan repo Quincy, lalu apt update.
  2. Di semua host, bersihkan signature delapan NVMe data dengan sgdisk -Z.
  3. Buat /etc/ceph di semua node.
  4. Di controller01, tulis ceph.conf dengan public network 192.168.194.0/24 dan cluster network 192.168.193.0/24.
  5. Jalankan cephadm bootstrap dengan --mon-ip 192.168.194.11, user dashboard admin, dan --skip-monitoring-stack.
  6. Sebarkan /etc/ceph/ceph.pub ke controller02, controller03, dan hyperconverged01.
Hasil yang diharapkan: MON pertama aktif di .11, dashboard Ceph dapat dibuka, dan tiga host lain menerima key Ceph.

Kenapa ini penting

--mon-ip harus berada di jaringan public Ceph (194), bukan storage (193). Kalau tertukar, host lain tidak bisa membentuk quorum pada jaringan yang salah.

Analogi praktis

MON pertama seperti kantor pusat yang membuka jaringan cabang. Alamat kantor pusat harus di jalan yang bisa ditemukan semua cabang.

Jebakan umum

sgdisk -Z menghapus signature disk. Pastikan /dev/nvme0n1–nvme7n1 adalah delapan disk data, bukan disk OS atau disk berisi data lama.

Memakai password contoh dari dokumen. Password dashboard di dokumen sumber sengaja diganti placeholder di modul ini. Tentukan password sendiri dan simpan di pengelola rahasia.

Melewati --skip-monitoring-stack tanpa alasan. Dokumen memakai flag ini karena monitoring dipisahkan ke Prometheus/Grafana, bukan ditumpuk di Ceph.

Pro-tip

Catat fsid yang dicetak cephadm bootstrap. Perintah cephadm shell --fsid ... di langkah berikutnya membutuhkannya.

ceph osd pool create vms 512
ceph osd pool set vms size 3

# Tunggu pool selesai, lalu aktifkan RBD
while [ $(ceph -s | grep creating -c) -gt 0 ]; do echo -n .; sleep 1; done
ceph osd pool application enable images rbd
ceph osd pool application enable volumes rbd
ceph osd pool application enable vms rbd
ceph osd pool ls
ceph df

Apa yang kamu lakukan

  1. Masuk ke shell Ceph memakai fsid dari bootstrap.
  2. Tambahkan tiga host, beri label _admin dan osd-node sesuai peran.
  3. Terapkan MON dan MGR hanya pada tiga controller.
  4. Tambahkan delapan OSD NVMe per host—total 32 OSD pada contoh dokumen.
  5. Matikan PG autoscale, buat pool images 128, volumes 256, vms 512, semuanya size 3, lalu aktifkan aplikasi rbd.
Hasil yang diharapkan: ceph -s menunjukkan HEALTH_OK, 32 OSD up/in, dan tiga pool RBD terlihat di ceph osd pool ls.

Kenapa ini penting

Tiga pool inilah yang nanti dipakai Glance (images), Cinder (volumes), dan Nova (vms). Nama serta PG harus cocok dengan keyring dan globals.yml; kalau tidak, volume bisa dibuat tetapi tidak bisa ditulis.

Analogi praktis

OSD itu laci penyimpanan, pool itu lemari berlabel. Membuat label lemari sebelum lacinya terpasang hanya menghasilkan lemari kosong yang tidak bisa diisi.

Jebakan umum

Salah nama device. Perintah OSD menghapus dan memformat device. Pastikan /dev/nvme0n1–nvme7n1 adalah disk data, bukan disk OS.

Membuat pool sebelum OSD up. Tunggu OSD benar-benar up; pool bisa terbentuk tetapi tetap creating.

Pro-tip

Simpan output ceph osd tree setelah OSD ditambahkan. Saat ada disk bermasalah, output itu menjadi pembanding cepat untuk melihat host dan device yang berubah.

Buat keyring dan default pool untuk Glance, Cinder, Nova

OpenStack tidak memakai kunci admin Ceph. Tiga client dibuat dengan hak terbatas: glance ke images, cinder ke volumes dan images, serta nova ke vms dan images.

Keyring dan ceph.conf · hal. 83–84
# controller01 — tiga client dengan hak terbatas
ceph auth get-or-create client.glance \
  mon 'allow r' \
  osd 'allow class-read object_prefix rbd_children, allow rwx pool=images' \
  -o /etc/ceph/ceph.client.glance.keyring

ceph auth get-or-create client.cinder \
  mon 'allow r' \
  osd 'allow class-read object_prefix rbd_children, allow rwx pool=volumes, allow rwx pool=images' \
  -o /etc/ceph/ceph.client.cinder.keyring

ceph auth get-or-create client.nova \
  mon 'allow r' \
  osd 'allow class-read object_prefix rbd_children, allow rwx pool=vms, allow rx pool=images' \
  -o /etc/ceph/ceph.client.nova.keyring

# Default pool per client — /etc/ceph/ceph.conf
[client.glance]
rbd default data pool = images
[client.cinder]
rbd default data pool = volumes
[client.nova]
rbd default data pool = vms

# Sebarkan keyring dan ceph.conf
scp /etc/ceph/ceph.* controller02:/etc/ceph/
scp /etc/ceph/ceph.* controller03:/etc/ceph/
scp /etc/ceph/ceph.* hyperconverged01:/etc/ceph/

Apa yang kamu lakukan

  1. Buat tiga client Ceph dengan capability yang persis seperti dokumen.
  2. Tambahkan rbd default data pool untuk masing-masing client di /etc/ceph/ceph.conf.
  3. Sebarkan ceph.* ke semua host lewat scp.
  4. Verifikasi keyring ada di path yang sama di setiap host sebelum deploy OpenStack.
Hasil yang diharapkan: tiga keyring ada di /etc/ceph semua host, dan client dapat membaca pool-nya tanpa memakai kunci admin.

Kenapa ini penting

Keyring adalah identitas layanan. Nama file, user, dan pool harus sama dengan ceph_cinder_keyring, ceph_glance_keyring, dan ceph_nova_keyring di globals.yml. Satu salah nama berarti container tidak bisa membuka RBD.

Analogi praktis

Ini seperti memberi tiga kartu akses berbeda: petugas gambar hanya boleh masuk ruang images, petugas volume ke volumes, dan compute ke vms. Tidak ada yang membawa kunci master.

Jebakan umum

Menyalin keyring ke host yang salah. Semua host compute dan control perlu keyring yang relevan; deploy Kolla membaca file dari /etc/kolla/config di langkah berikutnya.

Memberi capability terlalu luas. Gunakan capability dari dokumen, bukan kunci admin, agar batas antar-layanan tetap jelas.

Pro-tip

Simpan checksum ceph.conf di satu host dan bandingkan setelah scp. File yang tidak identik sering menjadi sumber masalah “hanya satu host yang gagal”.

Deploy OpenStack, lalu isi layanan yang bisa dipakai

Deploy Kolla memakai konfigurasi Ceph yang sudah disalin ke /etc/kolla/config. Setelah deploy dan post-deploy, layanan diinisiasi: flavor, image, provider network, network internal, router, dan security group.

Deploy dan inisiasi · hal. 85–90
# controller01 — config Ceph untuk Kolla
mkdir -p /etc/kolla/config/{cinder,nova,glance}
mkdir -p /etc/kolla/config/cinder/cinder-volume/
cp /etc/ceph/ceph.conf /etc/kolla/config/cinder/
cp /etc/ceph/ceph.conf /etc/kolla/config/nova/
cp /etc/ceph/ceph.conf /etc/kolla/config/glance/
cp /etc/ceph/ceph.client.glance.keyring /etc/kolla/config/glance/
cp /etc/ceph/ceph.client.cinder.keyring /etc/kolla/config/cinder/cinder-volume/
cp /etc/ceph/ceph.client.nova.keyring /etc/kolla/config/nova/
cp /etc/ceph/ceph.client.cinder.keyring /etc/kolla/config/nova/

# Provider VLAN dan flatten snapshot
mkdir -p /etc/kolla/config/neutron
cat<<EOF | tee /etc/kolla/config/neutron/ml2_conf.ini
[ml2_type_vlan]
network_vlan_ranges = physnet1:188:189,physnet1:195:195
EOF

cat<<EOF | tee /etc/kolla/config/cinder.conf
[rbd-1]
rbd_flatten_volume_from_snapshot = true
EOF

# Deploy
docker load -i openstack-image.tar
kolla-ansible -v -i ~/multinode deploy
kolla-ansible -v -i ~/multinode post-deploy
pip install python-openstackclient

# admin-openrc.sh: aktifkan venv dan CA
source /root/openstack/os-venv/bin/activate
export OS_CACERT=/etc/ssl/certs/ca-certificates.crt

# Inisiasi layanan
source /etc/kolla/admin-openrc.sh
openstack flavor create --id 1 --ram 2048 --disk 20 --vcpus 1 m1.small
openstack flavor create --id 2 --ram 4096 --disk 40 --vcpus 2 m1.medium
openstack flavor create --id 3 --ram 8192 --disk 80 --vcpus 4 m1.large
openstack flavor create --id 4 --ram 16384 --disk 160 --vcpus 8 m1.xlarge

# Image Ubuntu 20.04 dan 22.04 (format qcow2)
wget https://cloud-images.ubuntu.com/focal/current/focal-server-cloudimg-amd64.img
openstack image create --container-format bare --public \
  --disk-format qcow2 --property os_type=linux \
  --file focal-server-cloudimg-amd64.img Ubuntu-20.04
wget https://cloud-images.ubuntu.com/jammy/current/jammy-server-cloudimg-amd64.img
openstack image create --container-format bare --public \
  --disk-format qcow2 --property os_type=linux \
  --file jammy-server-cloudimg-amd64.img Ubuntu-22.04

# Provider network (VLAN 192) dan subnet eksternal
openstack network create --external --share \
  --provider-physical-network physnet1 \
  --provider-network-type vlan --provider-segment 192 external-net
openstack subnet create --network external-net \
  --gateway 192.168.192.1 --no-dhcp \
  --subnet-range 192.168.192.0/24 external-subnet

# Network internal, router, security group
openstack network create internal-net
openstack subnet create --network internal-net \
  --allocation-pool start=172.18.10.10,end=172.18.10.254 \
  --dns-nameserver 8.8.8.8 --gateway 172.18.10.1 \
  --subnet-range 172.18.10.0/24 internal-subnet
openstack router create router
openstack router set --external-gateway external-net router
openstack router add subnet router internal-subnet
openstack security group create 'Allow SSH and ICMP' --description 'Allow SSH and ICMP'
openstack security group rule create --protocol icmp 'Allow ICMP'
openstack security group rule create --protocol tcp --ingress --dst-port 22 'Allow SSH'

Apa yang kamu lakukan

  1. Salin ceph.conf dan tiga keyring ke subtree /etc/kolla/config yang sesuai.
  2. Tambahkan ml2_conf.ini untuk VLAN provider 188:189,195:195 dan cinder.conf untuk flatten snapshot.
  3. Muat image container dari openstack-image.tar, lalu jalankan deploy dan post-deploy.
  4. Pasang client, aktifkan venv dan CA di admin-openrc.sh, lalu buat flavor, image, network, router, dan security group.
Hasil yang diharapkan: empat flavor, image Ubuntu 20.04/22.04, external-net, internal-net, router, dan security group Allow SSH and ICMP terdaftar.

Kenapa ini penting

deploy hanya memasang layanan. Tanpa flavor, image, dan network, cloud belum bisa dipakai membuat instance. Network eksternal memakai segmen 192, sedangkan ml2_conf.ini mendaftarkan rentang 188–189 dan 195 untuk physnet1—keduanya keputusan desain dokumen yang harus dibaca bersama peta VLAN.

Analogi praktis

Deploy itu membangun gedung dan memasang listrik. Flavor, image, dan network adalah perabot serta alamat yang membuat gedung benar-benar bisa dipakai.

Jebakan umum

Menjalankan deploy sebelum keyring disalin. Container Cinder/Glance/Nova akan hidup tanpa akses ke pool yang benar.

Mengubah rentang VLAN tanpa peta. ml2_conf.ini mendaftarkan 188–189 dan 195; external-net dibuat pada segmen 192. Ikuti pemetaan dokumen, jangan menebak bahwa semua segmen harus masuk satu rentang.

Pro-tip

Setelah post-deploy, segera source /etc/kolla/admin-openrc.sh di shell baru. Jangan mencampur shell yang masih memakai kredensial lama.

FAQ

Pertanyaan yang muncul saat implementasi

Apakah saya harus memakai empat host persis seperti contoh?

Tidak. Empat host adalah topologi contoh di dokumen: tiga controller dan satu hyperconverged. Yang harus dipertahankan adalah tiga MON/MGR dan replication 3 agar cluster tetap memiliki toleransi kegagalan. Jumlah compute bisa ditambah pada fase scale-out (hal. 91).

Kenapa Ceph memakai dua jaringan, 193 dan 194?

Dokumen memisahkan public network 192.168.194.0/24 untuk komunikasi client/MON dan cluster network 192.168.193.0/24 untuk replikasi OSD. Pemisahan ini menjaga lalu lintas replikasi tidak berebut jalur dengan lalu lintas layanan.

Bolehkah saya memakai password dashboard Ceph dari dokumen?

Jangan. Modul ini sengaja menggantinya dengan placeholder. Tentukan password sendiri, simpan di pengelola rahasia, dan batasi akses dashboard. Nilai asli di dokumen adalah contoh implementasi, bukan rekomendasi produksi.

Apa bedanya deploy dan post-deploy?

deploy memasang container dan konfigurasi layanan. post-deploy menyelesaikan langkah pascapemasangan, termasuk membuat endpoint dan kredensial admin yang dipakai admin-openrc.sh. Keduanya dijalankan berurutan dari controller01.

Kalau Grafik Grafana kosong, apa yang pertama diperiksa?

Periksa tiga hal berurutan: (1) openstack compute service list dan volume service list untuk memastikan agent hidup; (2) konektivitas host ke Prometheus; (3) target exporter yang dipakai. Dokumen hanya menunjukkan dashboard akhir, bukan langkah konfigurasi exporter.

Apakah modul ini menggantikan dokumen asli?

Tidak. Ini jalur belajar yang diringkas dan dinetralkan dari dokumen implementasi. Untuk nilai environment, urutan persis, dan lampiran, tetap rujuk PDF halaman yang tercantum di setiap langkah.
