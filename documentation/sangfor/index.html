03 Model mental

Perbedaannya bukan ukuran server. Perbedaannya adalah cara resource diikat.

Di infrastruktur tradisional, CPU, disk, dan jaringan “menempel” pada satu kotak. Di HCI, ketiganya dilepas dari kotak dan dijadikan kolam yang bisa dibagi. Toggle di bawah menunjukkan perubahan itu.

Tiga pulau yang tidak saling bicara

Setiap aplikasi punya server, storage, dan jalur jaringannya sendiri. Kapasitas yang tersisa di satu pulau tidak bisa dipakai pulau lain — walaupun pulau sebelah sedang kehabisan resource.

  • Kapasitas dibeli per perangkat, bukan per kebutuhan.
  • Utilisasi rendah karena resource terkurung di tiap silo.
  • Setiap lapisan punya console dan siklus hidup sendiri.

Satu kolam, tiga lapisan, satu kontrol

Hardware x86 di semua node dianggap sebagai satu kesatuan. aSV menjalankan VM, aSAN menggabungkan disk lokal menjadi storage bersama, aNET menghubungkan dan mengamankan lalu lintasnya.

  • Tambah kapasitas = tambah node, bukan ganti seluruh sistem.
  • VM bisa memakai resource dari node mana pun di cluster.
  • Compute, storage, dan jaringan dikelola dari satu console.

04 Part 1 · Kenapa HCI

Infrastruktur lama bukan rusak. Ia hanya dioptimalkan untuk dunia yang sudah berubah.

Slide training menyebut lima masalah utama. Di bawah ini kelimanya diperjelas: apa yang terjadi secara teknis, bagaimana gejalanya di lapangan, dan apa biaya tersembunyinya.

01 / 05

Sulit diperluas

Hardware tidak bisa menyediakan resource secara dinamis untuk data dan beban kerja yang terus naik.

  • Menambah CPU atau RAM berarti membeli atau mengganti unit server.
  • Storage tumbuh per shelf atau per array, bukan per kebutuhan VM.
  • Pengadaan butuh minggu sampai bulan; beban kerja tidak menunggu.
Gejala: kapasitas menumpuk di node yang salah
02 / 05

Lambat masuk ke pasar

Arsitektur rumit dan proses compliance memperlambat peluncuran layanan baru.

  • Setiap layanan baru sering berarti hardware, kabel, dan ruang rak baru.
  • Ada rantai approval: budget, pengadaan, instalasi, hardening, uji.
  • Tim produk menunggu infrastruktur, bukan sebaliknya.
Gejala: “go-live” diundur karena menunggu server
03 / 05

O&M rumit

Setiap vendor membawa console sendiri, sehingga pengelolaan terpusat nyaris mustahil.

  • Satu insiden bisa memaksa admin membuka empat tool berbeda.
  • Skill terpecah per silo; sulit mencari pengganti saat orang kunci cuti.
  • Konfigurasi mudah “drift” karena diubah di tempat berbeda.
Gejala: MTTR naik karena waktu habis mencari akar masalah
04 / 05

Pemanfaatan resource rendah

Investasi awal besar, tetapi sebagian kapasitas tidak pernah dipakai.

  • Satu server sering hanya menjalankan satu aplikasi.
  • Materi sumber menyebut rata-rata pemanfaatan sekitar 15%.
  • Listrik, pendingin, dan rak tetap dibayar untuk kapasitas idle.
Gejala: CPU 8%, tapi tetap diminta server baru
05 / 05

Sulit berinovasi

Waktu tim IT habis untuk instalasi, provisioning, dan maintenance rutin.

  • Kapasitas berpikir tim tersedot ke pekerjaan “menjaga sistem hidup”.
  • Inisiatif baru selalu kalah prioritas melawan tiket operasional.
  • Bisnis mulai mencari jalan sendiri — muncul shadow IT.
Gejala: roadmap IT isinya upgrade, bukan layanan baru

Semuanya berasal dari satu pola

Resource diikat ke perangkat. Selama ikatan itu ada, lima masalah di samping akan terus muncul meskipun hardware diganti lebih cepat.

  • HCI memutus ikatan itu dengan pooling + kontrol berbasis software.
  • Bukan berarti HCI cocok untuk semua kasus — lihat bagian “kapan tidak cocok” di bawah.

05 Part 2 · Teknologi virtualisasi

HCI: compute, storage, dan jaringan di atas server x86 standar — dikelola sebagai satu sistem.

Kalau Part 1 menjelaskan mengapa, bagian ini menjelaskan bagaimana. Fokusnya bukan nama fitur, tapi aliran resource: dari disk lokal di tiap node sampai menjadi VM yang bisa dipindah.

Definisi kerja

Apa itu Hyper-Converged Infrastructure?

HCI menggabungkan komputasi, jaringan, dan storage ke dalam server x86 standar dengan bantuan teknologi virtualisasi. Resource dikumpulkan per node, sehingga kapasitas bertambah cukup dengan menambah node.

Yang membuatnya “hyper-converged” bukan sekadar hypervisor. Tiga hal ini harus ada bersamaan:

  • Storage terdistribusi — disk lokal semua node menjadi satu datastore, bukan SAN terpisah.
  • Jaringan software-defined — switching, routing, dan keamanan bisa dibentuk tanpa mengubah kabel.
  • Satu control plane — compute, storage, network, dan security terlihat di console yang sama.
  • Scale-out — menambah node menambah CPU, RAM, kapasitas, dan bandwidth sekaligus.

Jebakan definisi: “server + VMware + SAN” bukan HCI, walaupun semuanya virtual. HCI menghilangkan SAN sebagai perangkat terpisah dan menggantinya dengan storage yang berjalan di node yang sama.

x86

x86 standar

Tanpa hardware khusus
  • Memakai server umum, tidak terikat satu merek hardware.
  • Membuka pilihan pengadaan dan mengurangi vendor lock-in di lapisan fisik.
+N

Tambah node

Scale-out, bukan scale-up
  • Tambah node saat butuh CPU, RAM, atau storage lagi.
  • Kapasitas bertambah tanpa mengganti seluruh cluster.
1

Satu tempat kelola

Single pane of glass
  • Compute, storage, dan jaringan dikelola dari satu tempat.
  • Mengurangi perpindahan tool saat operasi dan troubleshooting.
06 Tiga pilar aCloud

aSV, aSAN, aNET: tiga mesin di balik satu platform.

Klik tiap tab. Perhatikan bahwa ketiganya bukan produk terpisah yang “ditempel”, melainkan lapisan software yang berjalan di cluster yang sama.

Server virtualization

aSV — memecah satu server fisik menjadi banyak VM

aSV adalah hypervisor yang memvirtualisasi server fisik. Setiap VM mendapat CPU, RAM, disk, dan NIC virtual, lalu menjalankan OS serta aplikasinya sendiri seperti server x86 biasa.

Bagi pengguna, VM lebih cepat disediakan dan lebih mudah diubah daripada server fisik. Bagi tim IT, beberapa VM berbagi hardware yang sama sehingga biaya investasi dan operasional turun.

  • Isolasi: crash atau perubahan konfigurasi di satu VM tidak otomatis menjatuhkan VM lain.
  • Elastis: tambah vCPU/RAM tanpa membongkar server; provisioning hitungan menit, bukan minggu.
  • Portabel: VM adalah kumpulan file/objek, sehingga bisa dipindah atau di-clone lebih mudah.
  • Terukur: konsumsi resource per VM terlihat, sehingga overcommit bisa diputuskan sadar, bukan tebak-tebakan.

Snapshot ≠ backup. Snapshot tinggal di storage yang sama dan ikut rusak kalau storage bermasalah. Backup butuh salinan independen di media/lokasi lain.

VMhypervisorhardware
Distributed storage

aSAN — semua disk lokal menjadi satu kolam storage

Sangfor Virtual Storage adalah sistem file terdistribusi yang memakai disk lokal dari server x86. Disk di semua node digabung menjadi satu volume virtual, lalu dibagi ke VM dari satu titik kontrol.

  1. Kontribusi disk. Setiap node menyumbang disk lokalnya ke cluster.
  2. Bentuk datastore. Sistem file terdistribusi menyatukan kapasitas menjadi satu pool.
  3. Sebar salinan. Data dipecah dan disalin ke beberapa node sesuai kebijakan replica.
  4. Sajikan ke VM. Lapisan virtualisasi mengakses pool lewat antarmuka NFS dan iSCSI.
  5. Tumbuh. Tambah node → kapasitas dan performa ikut bertambah (scale-out).
Analogi Lemari arsip bersama. Setiap ruangan menyumbang satu laci. Dokumen disalin ke beberapa laci di ruangan berbeda; kalau satu laci terbakar, salinan di laci lain masih bisa dibuka.
poolreplicadisk lokal
Network virtualization + NFV

aNET — jaringan yang dibangun dan dipantau dalam satu tampilan

Memindahkan VM tanpa mengubah kebijakan jaringan adalah masalah tersendiri. VLAN tradisional juga tidak cukup untuk memisahkan layanan dan pengguna secara aman dalam skala besar. aNET menjawab keduanya dengan pendekatan overlay + NFV.

  • Overlay Layer 2: VM bisa berpindah antar node tanpa mengubah topologi dan kebijakan jaringan.
  • Isolasi: pengguna dan layanan dipisahkan secara logis, bukan hanya lewat VLAN fisik.
  • NFV: routing, switching, firewall, dan application delivery menjadi layanan software yang fleksibel.
  • WYSIWYG: topologi digambar secara visual — apa yang digambar, itulah yang berjalan.

Realita lapangan: overlay tetap berjalan di atas jaringan fisik. Underlay yang lambat, MTU salah, atau uplink tanpa redundansi akan tetap menjadi sumber masalah — software tidak menghapus kebutuhan desain fisik yang benar.

07 Detail aSV

Dua tipe hypervisor — dan kenapa data center memilih yang bare-metal.

Perbedaan ini sering muncul di interview dan saat membandingkan produk. Kuncinya ada di posisi hypervisor terhadap sistem operasi.

Tipe II · Hosted

Hypervisor di atas OS host
  • Ada satu lapisan tambahan antara hardware dan VM.
  • Overhead lebih besar karena OS host ikut memakai resource.
  • Lebih mudah dipasang; umum untuk testing atau desktop.
VM → APP

Tipe I · Bare-metal

Hypervisor langsung di atas hardware
  • Hypervisor berjalan langsung di atas hardware.
  • OS dan aplikasi tamu berjalan di atas hypervisor.
  • Overhead rendah; umum dipakai di data center produksi.
VM → APP

aSV diposisikan sebagai hypervisor bare-metal. Materi sumber tidak merinci versi kernel atau teknisi internal; bagian ini menjelaskan model arsitekturnya, bukan detail implementasi.

09 Tiga lapis proteksi

RAID, replica, dan backup bukan pengganti satu sama lain.

Ini pembeda yang harus kamu bawa ke setiap diskusi desain. Ketiganya menjawab pertanyaan yang berbeda.

R

RAID

Melindungi dari disk rusak
  • Menjaga data tetap terbaca saat satu atau lebih disk dalam grup yang sama gagal.
  • Tidak melindungi dari file terhapus, ransomware, atau kesalahan manusia.
  • Berada di satu sistem/array yang sama.
2×

Replica aSAN

Melindungi dari node/disk gagal
  • Menyimpan 2–3 salinan data di node berbeda dalam cluster.
  • Menjaga layanan tetap jalan saat node hilang, tetapi ikut terhapus jika datanya dihapus.
  • Mengonsumsi kapasitas sesuai jumlah salinan.
B

Backup

Melindungi dari kehilangan logis
  • Salinan independen pada titik waktu tertentu, disimpan di media/lokasi terpisah.
  • Bisa memulihkan file, VM, atau seluruh sistem setelah ransomware/salah hapus.
  • Butuh jadwal, retensi, dan uji restore — bukan sekadar “sudah backup”.

Kalimat yang harus dihindari: “Datanya aman, kami sudah pakai replica 3.” Replica 3 menjaga ketersediaan saat hardware gagal, tetapi tidak mengembalikan data yang terhapus oleh admin, bug aplikasi, atau ransomware. Itu pekerjaan backup.

11 Keunggulan

Empat klaim utama — dan cara mengujinya.

Materi sumber merangkumnya sebagai Simple, Stable, Secure, Easy to Use. Berikut arti operasional masing-masing, plus pertanyaan yang perlu diajukan sebelum mempercayainya.

S

Simple · Sederhana

Lebih sedikit bagian yang digerakkan
  • Disebut sebagai arsitektur konvergensi penuh pertama di dunia — klaim vendor, perlu diverifikasi.
  • Bisa dimulai dengan hanya 2 node untuk kebutuhan kecil.
  • Topologi jaringan dibuat otomatis dengan pendekatan WYSIWYG.
  • Oracle/SQL bisa di-deploy dalam 6 langkah (klaim vendor).
  • VMware VM dapat dikelola di dalam sistem yang sama.
S

Stable · Stabil

Proteksi data bukan add-on
  • Backup gratis sudah tersedia di dalam sistem.
  • RPO = 0 diklaim lewat CDP (Continuous Data Protection).
  • Didesain untuk aplikasi kritikal.
  • Proteksi data menjadi bagian platform, bukan produk terpisah.
S

Secure · Aman

Keamanan sedekat workload
  • Micro firewall tersedia di dalam sistem.
  • Appliance keamanan virtual seperti vNGAF dan vIAG sudah built-in.
  • Kebijakan keamanan bisa ditempelkan ke VM, bukan menunggu perubahan kabel/firewall fisik.
E

Easy to Use · Mudah dipakai

Satu console untuk operator
  • Console manajemen terpadu sudah built-in.
  • Health check satu klik untuk seluruh platform.
  • Operator cukup belajar satu console, bukan banyak console.
  • Waktu onboarding staf baru lebih singkat.

Uji sebelum percaya: minta reference architecture, bukti uji kegagalan node, definisi RPO yang dipakai, cakupan lisensi backup/CDP, dan batasan ukuran cluster. Klaim “pertama di dunia” dan “RPO 0” adalah klaim vendor di materi training — jangan dipakai sebagai fakta eksternal tanpa verifikasi.

12 Part 4 · Produk

Sangfor aCloud: satu platform untuk compute, storage, network, dan NFV.

Bagian ini menjawab pertanyaan yang sering muncul di awal training: ini produk apa, namanya berubah-ubah bagaimana, dan kemampuan apa yang benar-benar ada di dalamnya.

Definisi produk

Apa itu aCloud (HCI)?

aCloud mengintegrasikan compute, storage, jaringan, dan teknologi lain, lalu mengelolanya dari satu platform. Integrasi itu bukan sekadar bundling: resource benar-benar dibagi dan dikendalikan bersama.

  • Satu platform manajemen — bukan satu console per lapisan.
  • Resource pool — CPU/RAM semua node jadi satu kolam; disk lokal jadi satu datastore.
  • NFV — fungsi jaringan dan keamanan berjalan sebagai appliance virtual.
Cara mengingat aCloud = “data center dalam satu produk”. Anda tetap punya server fisik, switch, dan disk — tetapi semuanya dipandang dan dikelola sebagai satu sistem, bukan kumpulan perangkat.

Compute

CPU + RAM
  • CPU dan RAM semua node digabung menjadi satu kolam resource.
  • VM baru mengambil resource dari kolam tersebut.

Storage

aSAN
  • Disk lokal membentuk satu kolam storage terdistribusi.
  • Kapasitas dan performa tumbuh dengan node.

Network

aNET
  • Overlay network, virtual switch, dan virtual router.
  • Topologi dibangun visual dan dipantau dari console.

NFV

Virtual appliance
  • Layanan keamanan dan jaringan sebagai software.
  • Bisa ditambahkan tanpa hardware baru.

  • Topologi digambar visual: apa yang digambar, itulah yang jalan.
  • Virtual router (vRouter), virtual switch (vSwitch), dan NFV.
  • Ringkasan perangkat dengan status running, stopped, dan alarm.
  • Perubahan kebijakan mengikuti VM, bukan port fisik.
15 NFV

Fungsi jaringan dan keamanan yang bisa di-deploy seperti VM.

Network Function Virtualization membuat perangkat fisik berubah menjadi layanan software. Hasil praktisnya: layanan baru bisa ditambahkan tanpa menunggu pengadaan appliance dan kabel.

Keamanan

NGAF
  • Web application firewall
  • Proteksi kerentanan
  • Scanner real-time
  • Analisis visualisasi

Kontrol akses

IAM
  • Manajemen bandwidth
  • Filter URL dan kontrol aplikasi
  • Autentikasi pengguna
  • Laporan trafik internet

Pengiriman aplikasi

ADC
  • Load balancing server
  • Load balancing link
  • SSL offloading
  • Optimasi aplikasi

Akselerasi & DR

Optimization
  • Akselerasi aplikasi
  • Pengurangan trafik (flow reduction)
  • VPN akselerasi
  • Optimasi disaster recovery

Kenapa NFV penting secara arsitektur: keamanan dan jaringan bisa ditempatkan tepat di samping VM yang dilindungi, bukan di ujung kabel. Konsekuensinya, perubahan topologi jadi keputusan software — lebih cepat diuji, tetapi juga menuntut tata kelola kebijakan yang rapi.

16 Contoh kasus

Masalah yang sama, cara penyelesaian yang berbeda.

Perhatikan bahwa HCI tidak hanya menjawab “biaya”. Ia juga menjawab bottleneck storage, kerapian kabel, dan kecepatan operasi.

Biaya tinggi: setiap kebutuhan baru berarti upgrade hardware dan ekspansi baru.

Hemat: tambah kapasitas hanya saat dibutuhkan; bayar sesuai pertumbuhan, scale-out node demi node.

Sulit dikelola: banyak vendor, banyak console, banyak prosedur.

Satu platform: keamanan, jaringan, switch, server, dan storage digabung dalam satu HCI.

Bottleneck storage: banyak VM berebut satu storage eksternal.

Storage terdistribusi: bottleneck eksternal dihilangkan; performa dan throughput naik seiring node.

Kabel dan hardware berantakan: setiap ekspansi menambah perangkat dan jalur baru.

Lebih rapi: lebih sedikit perangkat terpisah yang harus dibeli, dikabel, dan dirawat.

Manajemen terpadu

Satu dashboard, satu sumber kebenaran
  • Compute, storage, jaringan, dan keamanan dikelola di satu tempat.
  • Satu dashboard untuk penjadwalan resource, status VM, dan kesehatan node.
  • Penanganan insiden lebih cepat karena operator melihat seluruh sistem.
  • Tampilan bawaan untuk penggunaan CPU, memori, dan storage per node/datastore.

Akses VM dari browser

Tanpa install client khusus
  • Mendukung Chrome, Firefox, IE, dan browser kompatibel HTML5.
  • Console VM dibuka langsung dari antarmuka web manajemen.
  • Demo pada materi: VM Windows Server 2012 R2 diakses dari browser.
  • Memudahkan akses darurat tanpa menyiapkan jump host dengan client khusus.

Kapan HCI belum tentu pilihan terbaik: kebutuhan IOPS ekstrem dengan array all-flash khusus, lingkungan yang sangat heterogen dan tidak boleh distandardisasi, single-node edge dengan anggaran minimal, atau regulasi yang mewajibkan pemisahan fisik storage. HCI kuat di standardisasi dan skala bertahap — bukan di setiap skenario.

17 Poin penting

Kalau hanya lima hal yang boleh kamu ingat, ini dia.

01

Silo menciptakan biaya. Sistem IT terpisah-pisah menyebabkan biaya tinggi, penyediaan layanan lambat, operasi rumit, dan pemanfaatan rendah.

02

HCI menyatukan tiga resource. Compute, storage, dan jaringan berjalan di hardware x86 standar dan dikelola dari satu platform.

03

aCloud = aSV + aSAN + aNET. Server, storage terdistribusi, dan jaringan/NFV adalah tiga mesin di baliknya.

04

Generasi 3 menambah security. Konvergensi penuh berarti keamanan menjadi bagian platform, bukan produk terpisah.

05

Mulai kecil, tumbuh sesuai kebutuhan. Materi menyebut titik mulai 2 node; kapasitas dan performa bertambah dengan menambah node — bayar sesuai pertumbuhan.

24 istilah
HCI

Hyper-Converged Infrastructure. Compute, storage, dan jaringan digabung dalam satu platform berbasis software di atas x86.

aCloud

Nama platform HCI Sangfor pada rentang versi 5.8.6 ke atas; sejak 6.1.0 kembali disebut HCI.

aSV

Komponen virtualisasi server: hypervisor yang menjalankan VM di atas hardware fisik.

aSAN

Virtual storage terdistribusi yang menggabungkan disk lokal semua node menjadi satu datastore.

aNET

Virtualisasi jaringan Sangfor: overlay network, virtual switch/router, dan NFV.

NFV

Network Function Virtualization. Fungsi jaringan/keamanan yang berjalan sebagai appliance software.

Hypervisor

Lapisan software yang membuat dan menjalankan VM, serta membagi resource fisik ke VM tersebut.

VM

Virtual Machine. Komputer virtual dengan CPU, RAM, disk, dan NIC virtual, menjalankan OS sendiri.

Node

Satu server fisik dalam cluster HCI yang menyumbang CPU, RAM, dan disk.

Cluster

Kumpulan node yang dikelola sebagai satu sistem dan berbagi resource.

Datastore

Wadah storage logis tempat file/objek VM disimpan; di aSAN berasal dari pool disk lokal.

Replica

Salinan data pada failure domain berbeda untuk menjaga ketersediaan saat node/disk gagal.

Rebuild

Proses membuat ulang salinan data setelah node/disk diganti; memakai bandwidth dan waktu.

Overlay

Jaringan logis di atas jaringan fisik yang memungkinkan VM terhubung tanpa mengikuti port switch.

Underlay

Jaringan fisik di bawah overlay: switch, kabel, uplink, MTU, dan bandwidth.

NFS

Network File System. Protokol berbagi file yang dipakai lapisan virtualisasi untuk mengakses datastore.

iSCSI

Protokol block storage di atas IP yang juga dipakai untuk mengekspos datastore ke host.

RPO

Recovery Point Objective. Batas toleransi kehilangan data, diukur dari titik pemulihan terakhir.

CDP

Continuous Data Protection. Proteksi data terus-menerus; klaim RPO 0 pada materi adalah klaim vendor.

WYSIWYG

What You See Is What You Get. Topologi yang digambar di console adalah topologi yang berjalan.

IOPS

Input/Output Operations Per Second. Ukuran jumlah operasi disk per detik; penting untuk beban kerja acak.

MTTR

Mean Time To Repair. Rata-rata waktu untuk memulihkan layanan setelah insiden.

Scale-out

Menambah kapasitas dengan menambah node, bukan mengganti node dengan yang lebih besar.

Snapshot

Kondisi disk pada satu titik waktu. Bukan backup independen dan tidak menggantikan uji restore.

20 Kuis

Uji pemahaman: 8 pertanyaan, bukan hafalan.

Setiap jawaban punya pembahasan. Kalau salah, baca alasannya — di situ biasanya letak kesalahpahaman yang paling sering terjadi.

0/8Benar
01

Apa yang paling membedakan HCI dari virtualisasi server biasa?

Pembahasan: Virtualisasi server hanya memecah satu server menjadi VM. HCI menambahkan storage terdistribusi (aSAN) dan jaringan software-defined (aNET) yang dikelola bersama dari satu platform.
02

3 node × 6 disk × 8 TB, replica 2, cadangan ruang 20%. Berapa perkiraan kapasitas usable?

Pembahasan: Raw = 3 × 6 × 8 = 144 TB. Setelah cadangan 20% tersisa 115,2 TB. Dibagi dua salinan replica menjadi 57,6 TB usable.
03

Replica 2 melindungi kamu dari skenario yang mana?

Pembahasan: Replica menjaga ketersediaan saat kegagalan hardware. Penghapusan, enkripsi ransomware, dan korupsi logis akan ikut tereplikasi ke semua salinan — itu ranah backup.
04

aNET menggabungkan dua pendekatan utama, yaitu…

Pembahasan: Overlay membangun jaringan Layer 2 logis agar VM bebas berpindah; NFV menyediakan routing, switching, keamanan, dan application delivery sebagai layanan software.
05

Apa yang ditambahkan pada HCI Generasi 3?

Pembahasan: Generasi 1 = compute + storage; generasi 2 = + networking; generasi 3 = + security (micro firewall, vNGAF, vIAG).
06

Versi 6.9.1 yang dibahas training ini memakai nama produk…

Pembahasan: Tabel penamaan: 5.8.6 ke atas = aCloud, lalu 6.1.0 ke atas kembali ke HCI. Versi 6.9.1 termasuk HCI.
07

Tipe hypervisor yang umum dipakai di data center produksi adalah…

Pembahasan: Tipe I berjalan langsung di atas hardware sehingga overhead lebih rendah. Tipe II memerlukan OS host dan biasanya dipakai untuk testing atau desktop.
08

Klaim “RPO 0 dengan CDP” sebaiknya diperlakukan sebagai…

Pembahasan: RPO 0 berarti tidak ada data yang boleh hilang. Klaim ini bergantung pada cakupan CDP, beban kerja, dan konfigurasi — materi sumber sendiri menandainya sebagai klaim vendor.

21 FAQ

Pertanyaan yang biasanya muncul setelah sesi.

Berapa node minimum untuk membangun cluster HCI?
Materi training menyebut cluster bisa dimulai dengan 2 node. Untuk produksi, jumlah node bukan satu-satunya faktor: bicarakan juga kebutuhan redundansi, kebijakan replica, dan skenario kegagalan yang harus ditoleransi. Jangan memilih jumlah node hanya dari satu angka di slide.
Apakah HCI membutuhkan switch jaringan khusus?
Model HCI memakai switch umum, bukan perangkat khusus. Namun kualitas underlay tetap menentukan: kapasitas uplink, redundansi, pengaturan MTU untuk overlay, dan segmentasi trafik storage. Switch murah tanpa desain yang benar tetap bisa menjadi bottleneck.
Apakah server yang sudah ada bisa langsung dipakai?
HCI berjalan di x86 standar, tetapi bukan berarti semua model server didukung. Selalu cek hardware compatibility list dan firmware yang direkomendasikan untuk versi 6.9.1. Memakai hardware di luar daftar berisiko pada dukungan dan stabilitas.
Kalau sudah pakai replica, apakah backup masih perlu?
Perlu. Replica melindungi dari kegagalan hardware, bukan dari penghapusan, ransomware, atau korupsi data. Backup menyimpan salinan independen pada titik waktu lain dan harus diuji restore-nya secara berkala.
Apakah HCI menghilangkan kebutuhan SAN sama sekali?
Dalam model HCI, SAN eksternal bukan lagi komponen wajib karena storage dibentuk dari disk lokal tiap node. Beberapa lingkungan tetap memakai storage eksternal untuk kebutuhan khusus, tetapi itu menjadi pilihan arsitektur, bukan keharusan.
Bisakah VM dipindahkan tanpa downtime?
Dengan resource pool bersama dan fitur live migration yang didukung, VM dapat dipindahkan antar node tanpa mematikan layanan. Syaratnya: konfigurasi jaringan dan storage mendukung, serta ada kapasitas di node tujuan. Selalu uji di lingkungan non-produksi.
Kalau punya 2 node, apakah bisa memakai replica 3?
Replica 3 membutuhkan tiga failure domain yang independen. Dengan dua node, salinan ketiga tidak punya node ketiga untuk ditempatkan, sehingga proteksi sebenarnya tidak sesuai harapan. Pilih jumlah replica berdasarkan jumlah node dan kegagalan yang ingin ditoleransi.
Apa beda aCloud dan HCI?
Keduanya merujuk produk yang sama pada periode berbeda. Versi 5.8.6 ke atas memakai nama aCloud, lalu 6.1.0 ke atas kembali ke HCI. Training ini membahas 6.9.1, jadi sebutannya HCI.
Apakah RPO 0 berarti tidak akan ada data yang hilang?
RPO 0 berarti target kehilangan data mendekati nol pada konfigurasi yang didukung. Itu bukan jaminan absolut: tetap bergantung pada cakupan proteksi, jenis beban kerja, dan kondisi kegagalan. Perlakukan sebagai klaim yang perlu diverifikasi dengan skenario uji.
