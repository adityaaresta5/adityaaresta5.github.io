Vinchin adalah VM tamu di dalam ESXi

Vinchin dipasang sebagai virtual appliance: satu ISO all-in-one berisi sistem operasi, database metadata, web server, dan engine backup. Ada tiga lapisan yang harus benar sebelum halaman login bisa dibuka.

  • 1Storage: ISO installer dan disk virtual 100 GB berada di datastore ESXi. Virtual CD/DVD membaca ISO dari datastore.
  • 2Profil VM: guest OS Linux → Red Hat Enterprise Linux 8 (64-bit) menentukan controller SCSI, VMXNET3, dan manajemen memori.
  • 3Jaringan: IP statis dipakai administrator untuk membuka console dan nanti dipakai Vinchin untuk memanggil vCenter lewat FQDN.

Upload ISO Vinchin ke Datastore ESXi

Media instalasi harus berada di dalam storage yang dibaca hypervisor. Membaca ISO langsung dari laptop administrator (Client Device) membuat proses instalasi bergantung pada koneksi browser.

Apa yang kamu lakukan

  1. Buka web console VMware ESXi: https://<IP-ESXi>, lalu login.
  2. Masuk ke menu Storage, pilih datastore target, lalu klik Datastore browser.
  3. Buat folder khusus agar rapi—contoh pada sumber: iso_images. Gunakan Create directory.
  4. Buka folder tersebut, klik Upload, lalu pilih file installer Vinchin (.iso).
  5. Tunggu indikator unggah selesai dan file ISO muncul utuh di daftar file sebelum lanjut membuat VM.

Kenapa ini penting

ESXi memerlukan ISO di datastore internal atau NFS bersama agar virtual CD/DVD drive membacanya dengan kecepatan I/O storage host. Ini juga memutus ketergantungan pada koneksi browser laptop.

Sumber menyebut risiko konkret: instalasi via ISO lokal laptop sering terputus di tengah proses ketika bandwidth atau sesi browser hilang.

Jebakan umum

  • Memilih Client Device. ISO dibaca dari laptop; risiko disconnect saat instalasi berjalan.
  • Mengunggah ke folder yang salah. Nanti sulit menemukan ISO saat mengisi CD/DVD Drive; buat folder khusus.
  • Menganggap unggahan selesai. Tunggu sampai file benar-benar muncul; jangan menutup tab terlalu cepat.
  • Mengekstrak ISO. Virtual CD/DVD membutuhkan file .iso utuh, bukan isi foldernya.

Kriteria selesai

  • Akses web console ESXi berhasil dan datastore target sudah dipilih.
  • Folder iso_images (atau nama lain yang konsisten) sudah dibuat.
  • File ISO Vinchin terlihat di datastore browser dan ukurannya wajar—tidak 0 byte.

Buat VM baru dan beri nama

Langkah ini membuat wadah virtual machine kosong. Isi wizard belum menentukan sistem operasi; itu dipilih pada langkah berikutnya.

Apa yang kamu lakukan

  1. Di ESXi Host Client, buka menu Virtual Machines.
  2. Klik Create / Register VM.
  3. Pilih Create a new virtual machine, lalu klik Next.
  4. Isi nama VM. Contoh pada sumber: Vinchin-Backup-Server.
  5. Biarkan Compatibility pada nilai yang tersedia di host (rekaman menampilkan ESXi 7.0 U2 virtual machine).

Kenapa ini penting

Nama VM adalah identitas yang akan kamu cari di inventaris ESXi, saat memilih console, dan ketika Vinchin nanti dihubungkan ke vCenter. Nama yang jelas mencegah salah memilih VM—terutama di host yang menjalankan banyak mesin.

Memilih Create a new virtual machine (bukan register) memastikan ESXi membuat konfigurasi dan disk virtual baru.

Jebakan umum

  • Salah memilih “Register an existing virtual machine”. Opsi itu untuk file VM yang sudah ada, bukan membuat VM baru.
  • Nama terlalu generik. Gunakan nama yang menandakan fungsi, misalnya Vinchin-Backup-Server.
  • Mengubah Compatibility tanpa alasan. Nilai default host sudah sesuai; menurunkannya membatasi fitur virtual hardware.

Kriteria selesai

  • Wizard Create a new virtual machine terbuka dan nama VM sudah diisi.
  • Compatibility menunjukkan versi virtual machine yang didukung host.
  • Kamu berada di halaman Select storage atau Select a name and guest OS untuk lanjut.

Pilih Guest OS: Linux, RHEL 8 (64-bit)

Profil guest OS memberi tahu ESXi jenis driver dan perangkat virtual yang harus disiapkan. Vinchin berbasis Rocky Linux 8.x—turunan yang binary-compatible dengan RHEL.

Apa yang kamu lakukan

  1. Pada dropdown Guest OS family, pilih Linux.
  2. Pada dropdown Guest OS version, pilih Red Hat Enterprise Linux 8 (64-bit).
  3. Periksa kembali nama VM, lalu klik Next.

Kenapa RHEL 8 64-bit?

Sumber menjelaskan Vinchin versi terbaru dibangun di atas Rocky Linux 8.x. Profil guest OS di ESXi memengaruhi tiga hal:

  • Controller SCSI yang dipilihkan wizard—termasuk opsi paravirtual seperti VMware Paravirtual.
  • Virtual network card default VMXNET3 yang disebut berkecepatan 10 Gbps.
  • Manajemen memori (ballooning) dan integrasi VMware Tools.

Memilih profil ini menjaga stabilitas driver kernel OS Vinchin saat berkomunikasi dengan hardware virtual ESXi.

Jebakan umum

  • Memilih keluarga Windows. Profil hardware dan driver yang disiapkan tidak cocok dengan ISO Linux Vinchin.
  • Memilih versi 32-bit. ISO appliance modern berjalan 64-bit; pilihan 32-bit membatasi alamat memori.
  • Tidak mencocokkan versi ISO. Sumber menyebut 8.x, tetapi layar installer pada rekaman menampilkan Rocky Linux 9.2. Cocokkan profil dengan ISO yang benar-benar kamu unduh; jika ragu, ikuti panduan versi ISO tersebut.

Kriteria selesai

  • Guest OS family = Linux.
  • Guest OS version = Red Hat Enterprise Linux 8 (64-bit) (atau versi yang sesuai ISO-mu).
  • Nama VM sudah final dan mudah dikenali di inventaris.

Pilih datastore untuk disk VM

Wizard meminta lokasi penyimpanan disk virtual. Ini berbeda dari lokasi file ISO, meskipun keduanya bisa berada di datastore yang sama.

Apa yang kamu lakukan

  1. Pada halaman Select storage, pilih datastore target untuk menampung disk VM.
  2. Pastikan datastore memiliki ruang untuk disk OS minimal 100 GB yang akan dibuat pada langkah berikutnya.
  3. Klik Next untuk masuk ke Customize settings.

Kenapa ini penting

Datastore adalah tempat file disk virtual (.vmdk) hidup. Jika ruang tidak cukup, pembuatan disk atau operasi VM bisa gagal. Sumber juga menekankan agar ISO dan disk VM berada di storage yang stabil dan cepat.

Memilih datastore yang tepat sejak awal menghindari migrasi disk setelah OS terpasang.

Jebakan umum

  • Memilih datastore hampir penuh. VM butuh ruang untuk disk 100 GB plus file pendukung.
  • Mengira ini lokasi ISO. File ISO dipilih terpisah di CD/DVD Drive pada Langkah 6.
  • Tidak mencatat nama datastore. Saat troubleshoot, kamu perlu tahu di mana disk dan ISO berada.

Kriteria selesai

  • Datastore target sudah dipilih dan punya ruang untuk disk 100 GB.
  • Kamu sudah berada di halaman Customize settings.

Alokasikan CPU, RAM, dan disk OS

Sumber menetapkan batas minimum: 4 vCPU, 8 GB RAM, dan 100 GB disk OS. Nilai ini bukan angka kosmetik—Vinchin melakukan deduplikasi dan kompresi saat data mengalir.

Apa yang kamu lakukan

  1. Di Customize settings, atur CPU minimal 4 vCPU.
  2. Atur Memory minimal 8 GB.
  3. Atur Hard disk OS minimal 100 GB.
  4. Biarkan controller dan network adapter pada nilai yang disarankan wizard untuk profil RHEL 8.
  5. Lanjut ke pengaturan CD/DVD Drive 1 pada langkah berikutnya—jangan klik Finish dulu sebelum ISO terpasang.

Kenapa RAM & CPU sebesar itu?

Vinchin menghitung hash table deduplikasi dan mengompresi data secara inline/real-time sebelum ditulis ke penyimpanan. Sumber memperingatkan: jika vRAM atau vCPU terlalu kecil (contoh 1 CPU / 2 GB RAM), backup bervolume besar akan lambat atau kehabisan memori (OOM Killer).

Disk 100 GB awal murni untuk OS, database PostgreSQL bawaan, dan log transaksi Vinchin—bukan untuk menampung data backup.

Mount ISO ke CD/DVD Drive 1 & aktifkan saat power on

Virtual optical drive harus menunjuk ke file ISO di datastore dan terhubung saat VM dinyalakan. Tanpa keduanya, VM tidak punya media boot.

Apa yang kamu lakukan

  1. Pada CD/DVD Drive 1, ubah sumbernya menjadi Datastore ISO file.
  2. Klik Browse, cari file ISO Vinchin yang diunggah pada Langkah 1, lalu pilih file tersebut.
  3. Centang Connect at power on.
  4. Periksa kembali daftar hardware: 4 vCPU, 8 GB RAM, disk 100 GB, CD/DVD berisi ISO.
  5. Klik Next, tinjau ringkasan, lalu Finish.

Kenapa ini penting

Virtual CD/DVD adalah satu-satunya jalur boot pada tahap ini. Jika drive tidak terhubung saat power on, firmware virtual tidak akan menemukan media instalasi. Sumber menyebut gejala tepatnya: No bootable device found.

Jebakan umum

  • Lupa “Connect at power on”. Ini penyebab paling langsung dari No bootable device found.
  • Memilih “Client Device”. Drive membaca ISO dari laptop, bukan dari datastore—rawan terputus.
  • Menekan Finish sebelum ISO dipilih. Kamu harus mengedit VM lagi sebelum bisa boot.
  • Memilih file ISO yang salah. Pastikan nama file cocok dengan installer Vinchin yang dimaksud.

Nyalakan VM dan buka remote console

Setelah VM dibuat, nyalakan dan buka console-nya. Semua langkah installer berikutnya terjadi di dalam jendela console, bukan di tab utama ESXi.

Apa yang kamu lakukan

  1. Pilih VM Vinchin-Backup-Server di inventaris ESXi.
  2. Klik Power on.
  3. Buka tampilan console: Launch remote console atau Launch web console.
  4. Tunggu hingga jendela console menampilkan proses boot—bukan layar kosong atau pesan media tidak ditemukan.

Kenapa ini penting

Installer Vinchin adalah aplikasi grafis di dalam VM. Tanpa console, kamu tidak bisa memilih menu boot, mengatur zona waktu, memilih disk, atau mengisi IP.

Console juga menjadi alat diagnosa pertama jika VM tidak menemukan media boot.

Jebakan umum

  • Menutup jendela console. Instalasi tetap berjalan, tetapi kamu kehilangan kendali atas wizard.
  • Browser memblokir pop-up console. Izinkan pop-up untuk alamat ESXi agar jendela console terbuka.
  • Mengira VM hang. Beri waktu boot; frame sumber menunjukkan installer baru mulai setelah beberapa saat.

Kriteria selesai

  • Status VM Powered On.
  • Jendela remote console/web console terbuka dan menampilkan aktivitas boot.
  • Tidak ada pesan No bootable device found.

Pilih “Install Rocky Linux 8.x” di menu GRUB

Menu boot installer punya hitung mundur 60 detik. Pilih baris instalasi paling atas, lalu tekan Enter untuk memuat kernel dan wizard Anaconda.

Apa yang kamu lakukan

  1. Di menu boot GRUB pada console, pilih baris paling atas: Install Rocky Linux 8.x.
  2. Tekan Enter sebelum hitung mundur 60 detik berakhir.
  3. Tunggu kernel dan installer dimuat hingga halaman Installation Summary muncul.

Kenapa ini penting

Pilihan ini memuat kernel Linux instalasi ke memori VM dan meluncurkan Anaconda Installer. Opsi pertama menjalankan kernel dengan parameter instalasi grafis.

Installer Vinchin sudah disesuaikan agar dependensi ikut terpasang otomatis—Nginx, database internal, Python runtime, LVM utilities, dan daemon backup—tanpa instalasi repositori manual dari internet.

Jebakan umum

  • Membiarkan hitung mundur habis. Boot bisa berlanjut ke opsi default yang bukan maksudmu; pilih dan tekan Enter.
  • Memilih opsi uji media. Itu bukan instalasi; kamu hanya memeriksa media dan tidak masuk wizard.
  • Mematikan VM saat kernel dimuat. Tunggu sampai installer grafis benar-benar tampil.

Kriteria selesai

  • Baris Install Rocky Linux 8.x dipilih dan Enter sudah ditekan.
  • Layar grafis Installation Summary muncul.
  • Tidak ada pesan kernel panic atau media read error.

Atur Time & Date

Zona waktu bukan detail kosmetik. Jadwal backup, sertifikat, dan urutan restore point bergantung pada jam sistem.

Apa yang kamu lakukan

  1. Pada Installation Summary, klik Time & Date.
  2. Pilih Region (contoh sumber: Asia) dan City (contoh: Jakarta, Shanghai, atau kotamu).
  3. Periksa jam yang ditampilkan, lalu klik Done.

Kenapa waktu & NTP vital?

  • Jadwal backup reguler (cron/schedule) bergantung pada waktu sistem.
  • Sertifikat SSL dan token API ke vCenter ditolak jika selisih waktu melebihi ambang toleransi—sumber menyebut maksimal sekitar 5 menit.
  • Katalog restore point dan snapshot chain memerlukan timestamp presisi agar urutan backup inkremental tidak rusak.

Pilih Installation Destination

Installer harus tahu disk mana yang boleh diformat. Di modul ini hanya ada satu virtual disk 100 GB untuk OS.

Apa yang kamu lakukan

  1. Klik Installation Destination pada Installation Summary.
  2. Pastikan virtual disk 100 GB sudah tercentang.
  3. Biarkan Storage Configuration pada opsi Automatic.
  4. Periksa keterangan 1 disk selected; 100 GB capacity, lalu klik Done.

Kenapa ini penting

Ini adalah konfirmasi target penulisan sistem operasi. Jika tidak ada disk yang dipilih, installer tidak akan mengizinkan proses instalasi dimulai.

Partisi otomatis membagi ruang untuk OS, PostgreSQL, dan log sesuai kebutuhan appliance—tanpa kamu harus menghitung ukuran manual.

Jebakan umum

  • Tidak mencentang disk. Tombol Begin Installation tetap tidak aktif.
  • Mengubah ke Custom tanpa rencana. Skema partisi manual bisa membuat instalasi gagal atau ruang tidak cukup.
  • Menambah disk lain di luar modul. Jika VM dimodifikasi, pastikan hanya disk OS yang dipilih.

Kriteria selesai

  • Disk 100 GB tercentang dan bertanda centang biru.
  • Storage Configuration = Automatic.
  • Keterangan bawah menunjukkan 1 disk selected; 100 GB capacity.

Aktifkan adapter jaringan & buka pengaturan IPv4

Adapter Ethernet di dalam installer harus dinyalakan. Setelah itu, buka dialog konfigurasi untuk mengubah metode alamat dari DHCP ke Manual.

Apa yang kamu lakukan

  1. Klik Network & Host Name pada Installation Summary.
  2. Nyalakan adapter Ethernet dengan menggeser toggle ke mode ON.
  3. Klik tombol Configure... di kanan bawah.
  4. Pilih tab IPv4 Settings—di sinilah alamat statis akan diisi pada langkah berikutnya.

Kenapa ini penting

VM bisa saja hidup tanpa jaringan, tetapi kamu tidak akan bisa membuka web console setelah instalasi. Menyalakan adapter dan membuka tab yang benar memastikan konfigurasi IP benar-benar diterapkan ke interface.

Dialog ini juga tempat kamu melihat nama interface—pada rekaman sumber: ens192.

Jebakan umum

  • Lupa menyalakan toggle ON. IP bisa diisi, tetapi interface tetap tidak aktif.
  • Salah tab. Pengaturan alamat ada di IPv4 Settings, bukan General atau IPv6.
  • Menutup dialog tanpa Save/Done. Perubahan tidak diterapkan ke instalasi.

Kriteria selesai

  • Adapter Ethernet berstatus ON.
  • Dialog Editing ens192 (atau nama adaptermu) terbuka.
  • Tab IPv4 Settings aktif dan siap diisi.

Tetapkan IP statis, gateway, dan DNS

Server backup tidak boleh bergantung pada alamat dinamis. Isi alamat tetap agar web console dan integrasi API selalu menunjuk ke host yang sama.

Apa yang kamu lakukan

  1. Ubah Method dari Automatic (DHCP) menjadi Manual.
  2. Klik Add, lalu isi contoh dari sumber: Address 172.16.26.199, Netmask 255.255.255.0, Gateway 172.16.26.1.
  3. Isi DNS servers dengan 8.8.8.8 (atau DNS internalmu).
  4. Klik Save, lalu klik Done pada halaman Network & Host Name.

Kenapa dilarang memakai DHCP?

  • Jika IP berubah setelah router restart atau lease habis, web console Vinchin tidak bisa diakses dari alamat lama.
  • Webhook atau plugin dari host fisik ke Vinchin akan terputus.
  • DNS wajib diisi agar Vinchin bisa me-resolve FQDN vCenter—contoh sumber: vcenter.corp.local.

  • Gateway di subnet berbeda. Server tidak bisa keluar dari jaringannya.
  • Memakai IP yang sudah dipakai host lain. Periksa tabel IP sebelum menetapkan.

Kriteria selesai

  • Method = Manual.
  • Address, Netmask, Gateway, dan DNS terisi serta konsisten satu subnet.
  • Save dan Done sudah diklik.

Jalankan instalasi: Begin Installation

Semua keputusan sudah dikunci. Klik tombol biru dan biarkan installer menulis paket ke disk sampai progres mencapai 100%.

Apa yang kamu lakukan

  1. Periksa sekali lagi Installation Summary: waktu, disk, dan jaringan sudah bertanda selesai.
  2. Klik tombol biru Begin Installation.
  3. Tunggu proses penyalinan package berjalan hingga progres 100%.
  4. Jangan menutup console atau mematikan VM selama proses berlangsung.

Kenapa ini penting

Pada tahap ini installer menulis sistem operasi dan seluruh komponen Vinchin ke disk 100 GB. Proses ini tidak bisa “dipercepat” dengan mengulang klik; interupsi justru membuat sistem tidak lengkap.

Begin Installation juga menjadi konfirmasi terakhir bahwa wizard menerima semua konfigurasimu.

Jebakan umum

  • Menutup tab console. Instalasi mungkin berlanjut, tetapi kamu kehilangan progres dan tombol Reboot.
  • Mematikan VM karena “terlalu lama”. Tunggu hingga installer menyatakan selesai.
  • Mengulang instalasi tanpa alasan. Jika ada error, baca pesan di console dulu sebelum memulai ulang.

Kriteria selesai

  • Begin Installation sudah diklik.
  • Progres instalasi berjalan dan akhirnya mencapai 100%.
  • Tidak ada interupsi pada VM atau console.

Reboot System setelah instalasi selesai

Setelah pesan Complete!, reboot VM. Startup pertama adalah momen service Vinchin diinisialisasi.

Apa yang kamu lakukan

  1. Tunggu hingga installer menampilkan pesan “Complete!”.
  2. Klik tombol Reboot System.
  3. Biarkan VM boot ulang dan tunggu hingga muncul prompt login terminal Linux.
  4. Jangan menutup console sebelum proses boot selesai—prompt login menandakan sistem hidup.

Kenapa ini penting

Reboot memindahkan sistem dari media installer ke disk yang sudah terpasang. Pada startup pertama, service daemon Vinchin diinisialisasi sehingga web console bisa melayani permintaan HTTPS.

Prompt login Linux adalah bukti bahwa OS selesai boot—sebelum itu, kegagalan jaringan atau service belum bisa disimpulkan.

Jebakan umum

  • Memaksa power off saat reboot. Beri waktu; mematikan VM di tengah startup bisa merusak inisialisasi layanan.
  • Menganggap reboot gagal karena layar berganti-ganti teks. Itu bagian normal dari proses boot.
  • Langsung membuka browser sebelum prompt login muncul. Service belum tentu siap.

Kriteria selesai

  • Pesan Complete! muncul dan Reboot System sudah diklik.
  • VM kembali menyala tanpa error boot.
  • Prompt login terminal Linux terlihat di console.

Buka web console Vinchin lewat HTTPS

Instalasi berakhir di halaman login. Buka alamat IP statis dengan HTTPS, lewati peringatan sertifikat self-signed, dan pastikan halaman login muncul.

Apa yang kamu lakukan

  1. Di browser laptop, buka https://<IP-Statis-Vinchin>—contoh sumber: https://172.16.26.199.
  2. Jika muncul peringatan Your connection is not private, klik Advanced.
  3. Klik Proceed to ... (unsafe) untuk melanjutkan ke host yang kamu percaya.
  4. Pastikan halaman Login Vinchin Backup & Recovery muncul.

Kenapa peringatan SSL muncul?

Server Vinchin memakai sertifikat self-signed bawaan untuk mengenkripsi jalur komunikasi web. Browser tidak mengenali penerbitnya, sehingga menampilkan peringatan. Sumber menyatakan ini normal dan aman dilewati di jaringan internal perusahaan.

Halaman login yang muncul adalah bukti akhir bahwa OS, service web, dan konfigurasi jaringan sudah benar.

Jebakan umum

  • Menulis http://. Gunakan https://; port web console adalah HTTPS.
  • Memakai IP yang salah. Cocokkan dengan alamat yang diisi pada Langkah 12.
  • Membuka terlalu cepat. Tunggu prompt login Linux muncul; service butuh waktu inisialisasi.
  • Melewati peringatan di jaringan asing. Hanya lanjutkan jika kamu yakin alamat itu milik server Vinchin-mu.

Kriteria selesai

  • https://<IP-Vinchin> terbuka dan bukan halaman error koneksi.
  • Peringatan sertifikat sudah dilewati dengan sadar.
  • Halaman login Vinchin Backup & Recovery tampil.

Istilah yang muncul di modul ini

Bacaan singkat agar istilah ESXi dan Linux tidak menghambat saat mengikuti langkah di atas.

VMware ESXi

Hypervisor tipe 1 yang menjalankan virtual machine langsung di atas hardware host.

ESXi Host Client

Antarmuka web untuk mengelola host ESXi: datastore, VM, console, dan konfigurasi lainnya.

Datastore

Penyimpanan tempat file ISO dan disk virtual VM berada—misalnya VMFS lokal atau NFS bersama.

Datastore browser

Jendela untuk menelusuri, membuat folder, dan mengunggah file ke datastore.

Virtual appliance / ISO

Satu image all-in-one berisi OS, database, web server, dan engine backup Vinchin.

Guest OS profile

Pilihan keluarga/versi OS di wizard ESXi yang menentukan driver dan perangkat virtual yang disiapkan.

VMXNET3

Adapter jaringan paravirtual VMware yang disebut berkecepatan 10 Gbps pada profil RHEL 8.

SCSI HotAdd / LAN-free

Mode transport backup yang membaca disk VM lain melalui bus storage host, bukan bandwidth LAN fisik.

GRUB

Bootloader yang menampilkan pilihan instalasi; pada modul ini kamu memilih baris “Install Rocky Linux 8.x”.

Anaconda Installer

Program instalasi Linux yang menampilkan Installation Summary dan menulis paket ke disk.

Deduplikasi & kompresi inline

Proses menghitung hash dan mengompresi data saat backup mengalir—karena itu butuh CPU dan RAM yang cukup.

NTP / sinkronisasi waktu

Penyesuaian jam sistem. Selisih besar dapat menggagalkan verifikasi sertifikat/API dan merusak urutan jadwal.

DHCP vs IP statis

DHCP memberi alamat dinamis; IP statis memberi alamat tetap. Server backup memerlukan yang kedua.

Self-signed certificate

Sertifikat HTTPS yang dibuat server sendiri. Browser memperingatkannya sampai sertifikat tepercaya dipasang.

FAQ

Pertanyaan yang sering muncul

Kebingungan umum saat pertama kali memasang Vinchin sebagai VM di VMware ESXi.

Bolehkah memakai Client Device untuk ISO?
Secara teknis bisa, tetapi modul sumber tidak menyarankannya. ISO yang dibaca dari laptop membuat instalasi bergantung pada koneksi dan sesi browser. Jika laptop sleep atau jaringan terputus, proses bisa gagal. Unggah ISO ke datastore (Langkah 1) lalu pilih Datastore ISO file.
Haruskah memilih RHEL 8 kalau ISO saya lebih baru?
Modul sumber memakai Linux → Red Hat Enterprise Linux 8 (64-bit) karena Vinchin berbasis Rocky Linux 8.x. Namun rekaman installer menampilkan Rocky Linux 9.2. Prinsipnya: pilih profil guest OS yang paling dekat dengan basis ISO yang kamu unduh, lalu verifikasi di panduan versi tersebut. Jangan memilih profil Windows.
Kenapa disk OS minimal 100 GB?
Sumber menyebut 100 GB murni untuk OS, database PostgreSQL bawaan, dan log transaksi Vinchin. Ini bukan kapasitas penyimpanan backup. Repository data dikonfigurasi setelah web console aktif.
Apakah DHCP benar-benar tidak boleh?
Sumber menegaskan server infrastruktur kritis seperti backup appliance tidak boleh memakai DHCP dinamis: alamat yang berubah memutus web console, webhook/plugin, dan integrasi API. Jika terpaksa, gunakan DHCP reservation berbasis MAC address agar alamat tetap.
VM menampilkan “No bootable device found”. Apa yang salah?
Penyebab paling langsung: opsi Connect at power on pada CD/DVD Drive tidak dicentang, atau drive tidak diarahkan ke ISO Vinchin. Matikan VM, edit pengaturan CD/DVD Drive 1, pilih Datastore ISO file, centang Connect at power on, lalu nyalakan lagi. Lab 2 mempraktikkan kombinasi ini.
Apakah aman melewati peringatan sertifikat?
Sumber menyatakan peringatan itu normal untuk instalasi pertama karena Vinchin memakai sertifikat self-signed. Aman dilewati di jaringan internal yang kamu percaya. Jangan melewatinya di jaringan asing atau jika alamat IP tidak kamu kenali.
Berapa lama total instalasi?
Rekaman sumber memotong proses menjadi blok 00:45–06:25, jadi durasi itu bukan waktu nyata. Waktu sebenarnya bergantung pada kecepatan datastore, CPU host, dan proses penulisan paket. Modul ini tidak mencantumkan estimasi yang tidak ada di sumber.
Apa yang dilakukan setelah halaman login muncul?
Modul sumber berhenti tepat di halaman login. Konfigurasi lisensi, penambahan storage, dan pendaftaran vCenter adalah tahap berikutnya di luar cakupan modul ini. Jangan menganggap instalasi selesai secara operasional sebelum tahap tersebut dikerjakan.
